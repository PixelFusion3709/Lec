1. AI · 머신러닝 · 딥러닝 — 무엇이 무엇을 품고 있나

세 단어는 경쟁 관계가 아니라 러시아 인형(마트료시카)처럼 포개진 관계입니다. 가장 큰 인형이 인공지능이고, 그 안에 머신러닝이, 그 안에 딥러닝이 들어 있습니다. 오늘 우리가 만들 것은 대부분 머신러닝이고, 6차시에 다룰 ChatGPT·Claude 같은 도구는 딥러닝 안의 생성형 AI입니다.

용어한 줄 정의오늘 만나는 예
인공지능사람이 하던 판단·인식·언어 같은 일을 기계가 대신하도록 만든 기술 전체. 규칙을 직접 짜 넣은 것도 포함됩니다.엘리베이터 층 배정, 세탁기 코스 선택
머신러닝사람이 규칙을 쓰지 않고, 예시 데이터를 많이 보여주면 기계가 규칙을 스스로 찾는 방식.3차시 텍스트 분류, 5차시 이미지 인식
딥러닝사람의 뇌 신경망을 흉내 낸 층(layer)을 깊게 쌓아, 특징까지 기계가 스스로 뽑아내는 머신러닝.4차시 CNN, Teachable Machine
생성형 AI분류·예측을 넘어 없던 결과물을 새로 만들어내는 딥러닝 모델.6차시 ChatGPT·Claude·이미지 생성
🍳 비유 — 요리사에게 김치찌개를 가르치는 두 가지 방법

규칙 기반(전통 AI)은 레시피를 한 줄씩 적어주는 것입니다. "돼지고기 100g, 김치 200g, 물 500ml, 10분 끓이기." 정확하지만 레시피에 없는 상황(신 김치, 묵은지)이 오면 무너집니다.
머신러닝은 잘된 김치찌개 1,000그릇과 망한 1,000그릇을 맛보게 한 뒤, "뭐가 다른지 네가 찾아봐"라고 하는 것입니다. 규칙을 사람이 쓰지 않아도, 요리사는 스스로 감을 잡습니다.
딥러닝은 그 요리사가 "짠맛·신맛·감칠맛"이라는 개념 자체를 스스로 발명해서 판단하는 단계입니다.

2. 인공지능 70년 — 두 번의 겨울과 세 번의 봄

AI는 한 번도 순탄하게 성장한 적이 없습니다. 기대가 부풀었다가 무너진 두 번의 "AI 겨울"을 거쳤고, 지금이 세 번째 봄입니다. 이 흐름을 알면 지금의 AI 열풍도 냉정하게 볼 수 있습니다.

1950
앨런 튜링, "기계는 생각할 수 있는가"
논문 〈Computing Machinery and Intelligence〉에서 튜링 테스트를 제안. 사람이 대화 상대가 기계인지 사람인지 구분하지 못하면 "생각한다"고 보자는 기준입니다. AI라는 말이 생기기 전에 나온 질문입니다.
1956
다트머스 회의 — "Artificial Intelligence" 탄생
존 매카시가 미국 다트머스 대학에 마빈 민스키·클로드 섀넌 등을 모아 두 달짜리 여름 워크숍을 엽니다. 여기서 '인공지능'이라는 용어가 처음 공식 사용되었습니다. 오늘날 AI의 공식 생일입니다.
1957
퍼셉트론 — 신경망의 조상
프랭크 로젠블랫이 사람 뉴런을 흉내 낸 퍼셉트론을 발표. 지금 모든 딥러닝의 최소 단위입니다. 그러나 1969년 민스키가 "XOR 문제조차 못 푼다"고 지적하며 연구가 급랭합니다.
1974~1980
첫 번째 AI 겨울 ❄️
약속한 성과가 나오지 않자 미국·영국 정부의 연구비가 끊깁니다. 컴퓨터 성능과 데이터가 모두 부족했던 것이 근본 원인이었습니다.
1980년대
전문가 시스템의 짧은 봄 → 두 번째 겨울
의사·정비사의 지식을 "만약 ~라면 ~하라" 규칙 수천 개로 옮긴 전문가 시스템이 기업에 팔립니다. 하지만 규칙을 사람이 계속 손으로 고쳐야 해서 유지비가 폭발, 1987년경 다시 겨울이 옵니다. 규칙 기반의 한계가 증명된 사건입니다.
1997
딥블루, 체스 세계챔피언을 이기다
IBM의 딥블루가 가리 카스파로프에게 승리. 다만 이것은 초당 2억 수를 계산하는 '무식한 계산'이었지, 배우는 AI는 아니었습니다.
2012
알렉스넷 — 딥러닝의 빅뱅 🔥
이미지 인식 대회 ImageNet에서 딥러닝 모델 AlexNet이 오류율을 26%→16%로 한 번에 낮춥니다. GPU·빅데이터·신경망이 만난 순간이며, 오늘날 AI 붐의 실질적 출발점입니다. 4차시에 배울 CNN이 바로 이 기술입니다.
2016
알파고 vs 이세돌 (서울)
바둑은 경우의 수가 우주의 원자 수보다 많아 "계산으로는 불가능"하다고 여겨졌습니다. 알파고는 강화학습으로 스스로 대국하며 배웠습니다. 한국에서 AI 관심이 폭발한 결정적 계기입니다.
2017
트랜스포머 논문 〈Attention Is All You Need〉
구글이 발표한 이 구조가 오늘날 모든 대형 언어모델(GPT·Claude·Gemini)의 뼈대입니다. 문장 전체를 한 번에 보며 "어느 단어가 중요한지" 스스로 가중치를 매기는 방식입니다.
2022~현재
생성형 AI 대중화
2022년 11월 ChatGPT 공개로 일반인이 AI를 직접 쓰는 시대가 열립니다. 이미지(Midjourney·DALL·E), 영상, 음악까지 확장되었고, 2023년 이후에는 AI가 도구를 사용하고 스스로 작업을 수행하는 AI 에이전트로 발전 중입니다.
🎯 강사 포인트 — 연표를 외우게 하지 마세요. 대신 "두 번의 겨울은 왜 왔는가" 하나만 남기면 됩니다. 답은 ① 컴퓨터 성능 부족 ② 데이터 부족 ③ 규칙을 사람이 직접 써야 했던 한계. 지금 봄이 온 이유는 이 셋이 모두 해결되었기 때문입니다.

# 방법 A. 규칙 기반 — 사람이 직접 규칙을 씁니다
def rule_spam(text):
    for word in ["대출", "광고", "무료", "당첨"]:
        if word in text:
            return "🚨 스팸"
    return "✅ 정상"

tests = ["무료 쿠폰 받으세요",
         "내일 회의 자료 보냅니다",
         "부모님 대출 서류 부탁드려요",
         "지금 즉시 무~료 이벤트 참여!"]

1. 머신러닝의 정의 — 프로그래밍이 뒤집힌다

전통 프로그래밍

데이터 + 규칙 → 답

사람이 규칙(프로그램)을 씁니다. "가로×세로 = 넓이"처럼 규칙이 명확한 일에 강합니다. 하지만 "이 사진이 고양이인가"의 규칙은 사람도 못 씁니다.

머신러닝

데이터 + 답 → 규칙

사람은 예시와 정답만 줍니다. 규칙은 기계가 찾아냅니다. 고양이 사진 1만 장에 "고양이"라고 이름표만 붙여주면 됩니다.

👶 비유 — 아기가 "강아지"를 배우는 방식

아기에게 "강아지는 다리 4개, 털이 있고, 코가 젖어 있으며, 꼬리가 있다"고 정의를 외우게 하는 부모는 없습니다. 그냥 길에서 볼 때마다 "저건 강아지야"라고 말해줄 뿐입니다. 수십 번 반복되면 아기는 한 번도 본 적 없는 품종도 강아지라고 맞힙니다. 정의를 배운 게 아니라 패턴을 배운 것입니다. 머신러닝이 정확히 이것입니다. 그래서 데이터가 곧 교재이고, 편향된 데이터를 주면 편향된 AI가 나옵니다.

2. 학습의 3단계 — 훈련 · 평가 · 예측

① 훈련 (Training) — 문제집을 푼다

가지고 있는 데이터의 약 70~80%를 모델에게 보여줍니다. 모델은 예측해보고, 틀린 만큼(=오차) 내부 숫자를 조금씩 고칩니다. 이 "조금씩 고치기"를 수만 번 반복하는 것이 학습입니다.

② 평가 (Testing) — 처음 보는 시험을 친다

남겨둔 20~30%는 훈련 중에 절대 보여주지 않습니다. 이걸로 시험을 봐야 진짜 실력을 알 수 있습니다. 훈련 데이터로 시험 보는 것은 답안지 보고 시험 치는 것과 같습니다.

③ 예측 (Prediction) — 현실에 투입한다

시험 점수가 만족스러우면 실제 새 데이터에 씁니다. 이때 모델은 답과 함께 확신도(confidence)도 알려줍니다. 확신도가 낮으면 "모르겠다"고 처리하는 것이 좋은 설계입니다. (3차시·7차시에서 직접 적용)

from sklearn.linear_model import LinearRegression
import numpy as np

# ① 데이터 준비 : X = 공부 시간, y = 시험 점수
X = np.array([[1],[2],[3],[4],[5],[6],[7],[8]])

🐍 코드 3 · ⚠️ 과적합 실험 — 100점인데 실력은 86점
from sklearn.tree import DecisionTreeClassifier
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

d = load_digits()          # 손글씨 숫자 데이터 1,797장
X_train, X_test, y_train, y_test = train_test_split(
    d.data, d.target, test_size=0.3, random_state=1)

print("복잡도 | 훈련 정확도 | 시험 정확도")
for depth in [1, 3, 5, 10, None]:
    m = DecisionTreeClassifier(max_depth=depth, random_state=1)
    m.fit(X_train, y_train)
    print(f"{str(depth):>6} |   {m.score(X_train,y_train)*100:5.1f}%   |   "
          f"{m.score(X_test,y_test)*100:5.1f}%")
실행 결과복잡도 | 훈련 정확도 | 시험 정확도 1 | 20.0% | 19.3% ← 너무 단순 (과소적합) 3 | 48.0% | 45.9% 5 | 68.7% | 68.5% ← 훈련≈시험 (건강함) 10 | 97.3% | 85.4% ← 벌어지기 시작 None | 100.0% | 86.3% ← 과적합! 14%p 격차
📚 비유 — 기출문제만 통째로 외운 수험생

훈련 정확도 100%인데 시험 정확도가 86%라는 것은, 문제집 답을 통째로 외웠지만 응용문제는 못 푸는 학생과 같습니다. 이것이 과적합(overfitting)입니다.

그래서 머신러닝에서 자랑해야 할 숫자는 훈련 정확도가 아니라 시험 정확도입니다. AI 성능 뉴스를 볼 때도 "어떤 데이터로 평가한 수치인가"를 먼저 확인해야 합니다.

해결책 3가지 — ① 데이터를 더 모은다 ② 모델을 덜 복잡하게 만든다(위 표의 depth=5) ③ 훈련/시험 데이터를 반드시 분리한다.

4. 🐍 파이썬 트랙 — 같은 모델을 코드 10줄로

🐍 규칙 없이, 예시만으로 스팸/후기 분류하기 20분
🐍 코드 1 · ML4K와 똑같은 일을 하는 파이썬 코드
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import make_pipeline

# ① 훈련 데이터 = ML4K의 "레이블 상자"와 완전히 동일
good = ["정말 재미있어요", "최고예요 감사합니다", "너무 좋아요",
        "친절해서 기분이 좋아요", "수업이 알차고 유익했어요",
        "설명이 이해가 잘 돼요", "다음에 또 듣고 싶어요", "완전 만족합니다"]
bad  = ["너무 지루해요", "최악이에요 실망했어요", "설명이 하나도 이해가 안 돼요",
        "시간 낭비였어요", "너무 어렵고 불친절해요", "다시는 안 들을래요",
        "진도가 너무 빨라서 힘들어요", "별로예요"]

X = good + bad
y = ["칭찬"]*len(good) + ["불평"]*len(bad)

# ② 학습 — ML4K의 [훈련시키기] 버튼과 같은 역할
model = make_pipeline(
    CountVectorizer(analyzer='char_wb', ngram_range=(2,3)),  # 글자 묶음 세기
    MultinomialNB())                                          # 확률로 판단
model.fit(X, y)

# ③ 테스트 — 훈련에 없던 새 문장으로!
for t in ["오늘 수업 정말 좋았어요", "너무 어려워서 이해가 안 됐어요",
          "감사합니다 최고", "시간이 아까웠어요"]:
    label = model.predict([t])[0]
    conf  = max(model.predict_proba([t])[0]) * 100
    print(f"'{t}' → {label} (확신도 {conf:.0f}%)")
실행 결과 — 규칙을 한 줄도 안 썼는데 전부 맞힙니다'오늘 수업 정말 좋았어요' → 칭찬 (확신도 100%) '너무 어려워서 이해가 안 됐어요' → 불평 (확신도 100%) '감사합니다 최고' → 칭찬 (확신도 100%) '시간이 아까웠어요' → 불평 (확신도 82%)
🔑 1차시와 비교해 보세요 — 오늘의 가장 중요한 순간

1차시 규칙 기반 코드에는 if "무료" in text 같은 규칙이 사람 손으로 들어 있었고, 예외에 뚫렸습니다.
위 코드에는 "이 단어가 있으면 칭찬"이라는 규칙이 단 한 줄도 없습니다. 오직 예시 16개만 줬을 뿐인데, 훈련에 없던 문장을 맞힙니다.

이 차이가 곧 "인공지능"과 "머신러닝"의 경계입니다. 그리고 이것이 1980년대 전문가 시스템이 실패한 자리에서 머신러닝이 이긴 이유입니다.

1. 컴퓨터의 눈 — 이미지는 숫자 격자다

스마트폰으로 찍은 사진 한 장은 가로 4,000 × 세로 3,000 = 1,200만 개의 점(픽셀)으로 되어 있습니다. 컬러 사진은 각 점마다 빨강·초록·파랑(RGB) 세 숫자가 있고, 각각 0~255 값을 가집니다. 즉 사진 한 장 = 숫자 3,600만 개입니다. 컴퓨터 비전은 이 숫자 더미에서 의미를 뽑아내는 기술입니다.

멀리서 보면 아름다운 그림이지만, 코 하나하나를 들여다보면 "몇 번 실을 여기에 놓아라"라는 지시의 나열일 뿐입니다. 컴퓨터가 보는 사진이 정확히 이 상태입니다. 컴퓨터는 그림을 보지 못하고 실 번호만 봅니다. 그래서 컴퓨터 비전의 과제는 "이 실 번호 배열에서 규칙적인 무늬를 찾아내라"가 됩니다.

👁 사람이 보는 것
💻 컴퓨터가 보는 것
🎯 강사 포인트 — 참가자에게 같은 숫자 3을 각자 그리게 한 뒤 숫자 표를 비교하게 하세요. 사람 눈에는 다 "3"이지만 숫자 표는 전부 다릅니다. 그래서 AI에게는 같은 3의 다양한 변형을 많이 보여주는 것이 필요합니다. 이것이 왜 데이터가 수천 장 필요한지에 대한 가장 직관적인 설명입니다.

3. 합성곱 — 작은 창으로 훑어서 특징 찾기

숫자 표에서 어떻게 "선"이나 "모서리"를 찾을까요? 답은 합성곱(convolution)입니다. 3×3짜리 작은 창(=필터, 커널)을 이미지 위에서 한 칸씩 밀면서, 창에 걸친 숫자들을 곱해서 더합니다. 필터의 모양에 따라 세로선만 튀어나오거나, 가로선만 튀어나옵니다.

세로 경계 검출 필터
[ -1 0 +1 ] [ -1 0 +1 ] [ -1 0 +1 ]

왼쪽은 빼고 오른쪽은 더합니다. 좌우 밝기가 급히 바뀌는 곳(=세로 경계)에서 큰 값이 나옵니다.

가로 경계 검출 필터
[ -1 -1 -1 ] [ 0 0 0 ] [ +1 +1 +1 ]

위는 빼고 아래는 더합니다. 위아래 밝기가 급히 바뀌는 곳(=가로 경계)을 찾아냅니다.

🔦 비유 — 어두운 방을 손전등으로 훑기

깜깜한 방에서 벽 전체를 한눈에 볼 수는 없습니다. 대신 작은 손전등으로 한 뼘씩 훑으면서 "여기 문틀이 있네", "여기 액자가 있네" 하고 파악합니다. 합성곱이 바로 이 손전등입니다.

더 중요한 점: CNN에서는 이 필터의 숫자들을 사람이 정하지 않습니다. "고양이/개를 구분하려면 어떤 필터가 유용한가"를 학습으로 기계가 직접 찾아냅니다. 딥러닝이 특별한 이유가 여기 있습니다.

4. CNN — 선에서 사물까지, 층층이 쌓아 올리기

합성곱 한 번으로는 "선"밖에 못 찾습니다. 그래서 합성곱 → 풀링을 여러 번 반복해 층을 쌓습니다. 이것이 CNN(합성곱 신경망)이고, 2012년 AlexNet이 이 구조로 이미지 인식의 판도를 바꿨습니다.

층하는 일비유 (얼굴 알아보기)
합성곱층필터로 훑어 특징맵을 만듭니다. 층이 깊어질수록 더 복잡한 패턴을 잡습니다.선 → 눈썹·콧날 → 눈·코·입 → 얼굴
풀링층가장 큰 값만 남겨 크기를 절반으로 줄입니다. 계산량이 줄고, 위치가 조금 달라도 견딥니다."눈이 정확히 어디"보다 "눈이 있다"가 중요
완전연결층모든 특징을 종합해 최종 점수를 냅니다."눈2·코1·수염 → 고양이다"라는 판정
출력층각 후보에 대한 확률을 내놓습니다. 합은 항상 100%.3차시의 "확신도"와 같은 개념
📌 결정적 사건 — 2012년 이미지넷(ImageNet) 대회에서 CNN 기반 AlexNet이 오류율을 26%에서 16%로 한 번에 10%p 낮췄습니다. 그 전까지는 "고양이의 특징이 무엇인지" 사람이 직접 정의해야 했는데, CNN은 특징 자체를 스스로 발견했습니다. 오늘날 얼굴인식·자율주행·의료영상이 모두 이 사건에서 출발했습니다.

import numpy as np
from sklearn.datasets import load_digits
img = load_digits().images[0]

# 세로 경계를 찾는 3×3 필터
kernel = np.array([[-1, 0, 1],
                   [-1, 0, 1],
                   [-1, 0, 1]])

# 3×3 창을 한 칸씩 밀면서 곱하고 더하기 = 합성곱
out = np.zeros((6, 6))
for r in range(6):
    for c in range(6):
        window = img[r:r+3, c:c+3]      # 창에 걸린 부분
        out[r, c] = (window * kernel).sum()

print("[특징맵 — 큰 양수 = 왼쪽 경계, 큰 음수 = 오른쪽 경계]")
print(np.array2string(out.astype(int), max_line_width=100))

from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.metrics import accuracy_score
import numpy as np

# ① 데이터 준비 (8×8 손글씨 숫자 1,797장)
digits = load_digits()

# ② 훈련용 80% / 시험용 20%로 분리 ← 2차시에서 배운 그것!
X_train, X_test, y_train, y_test = train_test_split(
    digits.data, digits.target, test_size=0.2, random_state=42)
print(f"훈련 {len(X_train)}장 / 시험 {len(X_test)}장")

# ③ 학습
model = KNeighborsClassifier(n_neighbors=3)
model.fit(X_train, y_train)

# ④ 평가 — 한 번도 안 본 데이터로!
pred = model.predict(X_test)
print("시험 정확도 :", round(accuracy_score(y_test, pred)*100, 1), "%")

# ⑤ 틀린 것만 골라 보기
wrong = np.where(pred != y_test)[0]
print(f"틀린 개수 : {len(wrong)} / {len(y_test)}")
for i in wrong[:5]:
    print(f"   정답 {y_test[i]} → AI 예측 {pred[i]}")

🎼 비유 — 음악 평론가 vs 작곡가

판별형 AI는 음악 평론가입니다. 곡을 듣고 "이건 재즈, 저건 록"이라고 분류합니다.
생성형 AI는 작곡가입니다. "재즈풍 곡 하나 만들어줘"라고 하면 세상에 없던 곡을 씁니다.

그런데 이 작곡가는 음악 이론을 이해해서 작곡하는 게 아닙니다. 수백만 곡을 들으며 "이 음 다음에는 보통 이 음이 온다"는 통계적 감각만 익힌 상태입니다. 이 사실이 다음 절의 환각 문제로 곧장 이어집니다.

3. 토큰 · 확률 · 온도 — 알아두면 쓸모 있는 3가지

🔤 토큰 (Token)

AI가 글을 자르는 단위. 단어보다 작습니다. 영어는 대략 1토큰 ≈ 4글자, 한국어는 1글자 ≈ 1~2토큰. AI 서비스 요금이 "토큰당 얼마"인 이유이고, 한국어가 영어보다 비싸게 계산되는 이유이기도 합니다.

🎲 확률 분포

AI는 매 순간 수만 개 토큰 각각의 확률을 계산합니다. 항상 1등만 고르면 문장이 단조로워서, 확률에 따라 무작위로 뽑습니다. 같은 질문에 매번 다른 답이 오는 이유입니다.

🌡 온도 (Temperature)

낮으면(0에 가까움) 안전하고 반복적인 답, 높으면 창의적이지만 엉뚱한 답. 보고서·요약은 낮게, 아이디어 발상은 높게가 원칙입니다.

4. 👻 환각 (Hallucination) — 가장 중요한 한계

환각이란 AI가 사실이 아닌 내용을 아주 그럴듯하게, 자신 있게 말하는 현상입니다. 거짓말하려는 의도가 있는 게 아닙니다. AI는 "참인 문장"이 아니라 "그럴듯한 문장"을 만들도록 학습되었기 때문에, 사실 여부를 스스로 판별할 수단이 애초에 없습니다.

7. 🐍 파이썬 트랙 — 15줄로 만드는 미니 언어모델

🐍 코드 1 · 다음 단어 확률 계산 + 문장 생성
import random
from collections import defaultdict, Counter

# ① 학습 데이터 (진짜 GPT는 이걸 수조 단어 규모로 씁니다)
text = """옛날 옛적에 작은 마을에 지혜로운 할머니가 살았어요
할머니는 매일 아침 마을 사람들에게 이야기를 들려주었어요
마을 사람들은 할머니의 이야기를 좋아했어요
어느 날 할머니가 마을을 떠났어요
마을 사람들은 할머니를 그리워했어요
그래서 사람들은 서로에게 이야기를 들려주기 시작했어요"""

# ② "학습" = 어떤 단어 다음에 어떤 단어가 왔는지 세기
words = text.split()
table = defaultdict(list)
for now, nxt in zip(words, words[1:]):
    table[now].append(nxt)

print("'마을' 다음에 올 수 있는 단어 :", dict(Counter(table['마을'])))

# ③ "생성" = 확률에 따라 다음 단어를 뽑기를 반복
random.seed(7)
current = "마을"
result = [current]
for _ in range(12):
    if current not in table:
        break
    current = random.choice(table[current])   # ← 확률적으로 선택
    result.append(current)

print("생성 결과 :", " ".join(result))
실행 결과'마을' 다음에 올 수 있는 단어 : {'사람들에게': 1, '사람들은': 2} 생성 결과 : 마을 사람들은 할머니의 이야기를 들려주기 시작했어요
🔍 seed를 바꿔보세요 — random.seed(7)의 숫자를 바꾸면 매번 다른 문장이 나옵니다. ChatGPT가 같은 질문에 매번 다르게 답하는 이유가 정확히 이것입니다. 그리고 학습 데이터에 없던 단어를 넣으면 아무 말도 못 합니다 — 3차시에서 "둘 다 아닌 문장"을 넣었을 때와 같은 한계입니다.
🐍 코드 2 · 학습 데이터를 늘리면 문장이 좋아진다 (직접 실험)
# 위 코드에 이어서 — 여러분이 좋아하는 글을 넣어보세요!
my_text = """여기에 좋아하는 노래 가사나 소설 한 단락을 붙여넣으세요
문장이 많을수록 생성 결과가 자연스러워집니다
같은 단어가 여러 번 나올수록 연결이 풍부해집니다"""

words2 = my_text.split()
table2 = defaultdict(list)
for now, nxt in zip(words2, words2[1:]):

 "질문_날씨": "오늘은 맑고 최고 24도입니다.",
 "작별":      "다음에 또 만나요!",
}

X = [t for k, v in DATA.items() for t in v]
y = [k for k, v in DATA.items() for _ in v]
bot = make_pipeline(
    CountVectorizer(analyzer='char_wb', ngram_range=(2,3)),
    MultinomialNB()).fit(X, y)

# ③ 확신도 안전장치 — 스크래치의 [정확도 < 60] 블록과 같은 역할
THRESHOLD = 0.5

def answer(q):
    label = bot.predict([q])[0]
    conf  = bot.predict_proba([q]).max()
    if conf < THRESHOLD:
        return f"🤔 아직 배우지 못한 질문이에요. (추측: {label}, {conf*100:.0f}%)"
    return f"{REPLY[label]}   [{label} · 확신도 {conf*100:.0f}%]"

for q in ["안녕!", "지금 시간이 어떻게 되나요", "내일 비 오나요",
          "잘 있어", "저녁 메뉴 추천해줘"]:
    print(f"👤 {q}")
    print(f"🤖 {answer(q)}\n")

3. ⚖️ AI를 만드는 사람이 반드시 짚어야 할 것

쟁점무엇이 문제인가내 프로젝트에서 확인할 것
편향
Bias		데이터가 한쪽으로 치우치면 AI도 치우칩니다. 특정 성별·연령·지역의 데이터만 학습하면 다른 집단에서 성능이 떨어집니다. AI는 데이터에 있는 차별을 그대로 학습합니다.내 데이터를 몇 명이 만들었나? 한 사람 말투만 들어 있지 않나?
책임
Accountability		AI가 틀렸을 때 누가 책임지나요? 개발자? 사용자? "AI가 그랬다"는 면책 사유가 되지 않습니다.내 프로그램이 틀리면 어떤 피해가 생기나? 사람이 최종 확인하는 절차가 있나?
개인정보
Privacy		얼굴·목소리·글은 모두 개인정보입니다. 동의 없이 수집·학습하면 법적 문제가 됩니다.다른 사람 사진을 동의받고 찍었나? 수업 후 데이터를 삭제할 것인가?
투명성
Transparency		왜 그렇게 판단했는지 설명할 수 없는 AI를 "블랙박스"라 합니다. 의료·채용·대출처럼 중요한 결정에서는 설명 가능성이 필수입니다.사용자에게 확신도를 보여주고 있나? "AI의 판단"임을 명시했나?
저작권
Copyright		생성형 AI의 학습 데이터와 결과물의 권리는 여전히 논쟁 중입니다. 나라마다 판단이 다릅니다.남의 사진·글을 학습에 썼나? 결과물을 공개할 수 있나?
